# Eight-source migration coverage

The historical results can be retained without loss, but **the current Curation register does not yet establish complete migration of every source assertion and its meaning**. The original three flow registries, seed mappings and unified result survive byte-for-byte. Six additional original files have now been recovered privately. Their mapping authorship, source versions, quantity semantics and row-level dispositions need explicit representation before “all previous work migrated” is justified. ## Concrete corrections needed

**Quarantine the literal `nan` placeholder identity.** In the in-house JSON, 1,194 rows share `placeholder_code="nan"`, spanning 552 names and 914 distinct target pairs. There are only 423 distinct non-`nan` codes. The old builder accepts the nonempty string and repeatedly overwrites the same dictionary entry. Its input metadata also reports 1,590 total placeholders and `unmatched_v2=-27`, while the file actually has 1,617 rows. Preserve each original row and recover its real source coordinate; do not adopt the surviving dictionary entry as a consolidated identity. Original-row audit (evidence `eight-source-row-audit`)

**Separate provider, mapper and verifier.** The external-source ledger credits HESTIA/Oxford and calls the mapping independent confirmation, while all 95 mapping rows name Eaternity and no verifier. The ledger also describes the Sentier placeholder workbook as cross-validation only and points its license attribution to the separate BAFU→EF mapping section; the builder actually adds the workbook's links to its weighted scorer. These are three distinct artifacts: Sentier's AGRIBALYSE placeholder workbook, the in-house placeholder JSON, and the 1,100-row Sentier BAFU mapping. Preserve their separate authorship, scope, versions and terms. Source audit (evidence `eight-source-capability-audit`)

**Keep dependent evidence dependent.** The historical result records 4,226 DDS links overlapping GLAD. The derived DDS file labels 4,220 rows `glad`; its fetcher assigns that label to blank comments, so even that classification is inherited software behavior rather than a fresh provider attestation. Adding the GLAD and DDS weights did not produce two independent observations. A migration needs source ancestry and duplicate dispositions, not another vote count. Pinned source and loader evidence (evidence `eight-source-capability-audit`)

**Preserve quantity and context beyond pair membership.** The GLAD loader reads nonunity conversion factors and proxy map types but feeds UUID-pair membership to the scorer. DDS drops source units and most conversion metadata. FEDEFL contributes names before matching. These source assertions can be preserved as evidence, but their original scope must accompany any upstream proposal or executable module. The titanium trace demonstrates why identity correspondence and quantity application are separate questions. Source audit (evidence `eight-source-capability-audit`), [titanium application review](titanium-quantity-application-2026-10-13.md)

## Retention and acceptance

The current three registry dumps, 3,920 seed mappings and full 83,869-alias mapping are byte-identical to their preserved baseline copies. All **71 Git-tracked CF tables and sidecars** inspected at `4bec1691…` remain byte-identical in the canonical checkout. This establishes retention, not their scientific correctness or application. The current `validation_report.json` describes 84,254 clusters from June, while the retained unified result has 83,869 clusters from August; that report cannot be relabelled as validation of this later result. CF inventory (evidence `eight-source-cf-inventory`), artifact identities (evidence `eight-source-capability-audit`)

The six newly recovered originals are the GLAD workbook, HESTIA CSV, derived DDS JSON, Sentier placeholder workbook, empty flowmapper JSON and in-house placeholder JSON. Each private copy was byte-checked against its canonical source. None matched an active Curation document hash at audit time. Their exact use in the historical run remains unproven because no original generation manifest pins those untracked input bytes; matching historical counts is only corroboration. The empty flowmapper artifact is preserved as a measured zero-contribution input. Recovery inventory (evidence `eight-source-capability-audit`)

Accept complete migration only when:

1. Every original input has an exact artifact identity, source-version scope, lineage and rights-aware evidence location; historical gaps remain explicit.
2. Every assertion has a retained, reviewable disposition: selected, rejected, duplicate, superseded or unresolved. Ordinary reference rows do not need to become thousands of invented findings.
3. Source coordinates, mapper and verifier attribution, context and directed quantity semantics survive comparison with the chosen Consensus snapshot.
4. Full historical results and factors remain available; scientific review, executable policy behavior, receiving checks and consumer adoption have separate evidence.

The source-file audit left the active register unchanged. The subsequent capability assessment registered its three receipts and three published/result receipts for local review, bringing the document count to 175. Every original case and package remains unchanged. Full audit and limits (evidence `eight-source-capability-audit`), [capability assessment](workbench-capability-assessment-2026-10-13.md)
