# Connect curation evidence without introducing a second decision engine

Keep Checks as build quality control and add a Curation register connecting
findings, proposals and the existing executable modules. GitHub remains the
discussion and review surface; the application reads a versioned register and
the existing ruling/transformer registries. This makes incomplete historical
provenance visible without changing which correction runs.

Execution, validation, scientific sign-off and release adoption remain separate.
Every approval names a revision and scope; a different revision cannot inherit
it. A module's presence in the source tree proves implementation exists, not
that it was applied in the displayed build. The local preview uses selected
public cases, with browser-only notes, while maintainers consider the schema
and the eventual review/update workflow.
